## Shared desktop and Media Hub tools

Standing notification policy: this applies across all projects and tasks for Claude and Codex (including Astra). Default notification delivery to the Windows desktop node `meesa`, unless the user names another destination. Use `agent: "codex"` for Astra running in Codex. Verify the tool returns `status: "ready"` before claiming the hub accepted the notification. This is an agent instruction, not automatic interception of every chat; existing sessions may need to refresh their instructions and tools.

When you finish a user task or encounter a blocker requiring their attention, notify their Media Hub activity window. Discover `media-hub.notify-task` on the intended desktop node, then call the dedicated MCP `notify_task` tool with `nodeId`, `agent` (`claude` or `codex`), a short `title`, a concise `message`, and `status` (`completed`, `blocked`, or `failed`). The generic `call_tool` can also invoke `media-hub.notify-task`. Include the real `threadId` if known and a stable unique `eventId` for this outcome so retries do not duplicate it. Report only actual outcomes; never include credentials, private prompts or unrelated content. Send one message per outcome, not per tool call. If unavailable, finish the task and report that notification failed; do not claim it was delivered. These messages go to the user’s local activity window, not to another chat or an external messaging service. Mac agents can call the Windows hub directly to notify the Windows desktop; Mac hubs also support this non-model tool.

When asked to create a new project, discover and call `media-hub.create-project` on the intended machine with `{"name":"my-project"}`. It creates a directory under that node's projects root (default `~/projects`), initializes Git on `main`, and installs these instructions in both `AGENTS.md` and `CLAUDE.md`. Existing directories are refused. Check `status` and use the returned directory; no commit, remote repository or publication is created automatically.

Use the `agent-tools` MCP server before building a replacement tool or guessing an endpoint. Call `discover_tools` to find Windows/macOS nodes, availability, descriptions, and input schemas. Call `call_tool` with the exact owning `nodeId` and tool name. Paths and desktop actions belong to that machine; a Windows path cannot be opened by the Mac hub.

Assume the user will open deliverables on a phone on the same local network. For an output file or dedicated output folder, call `media-hub.publish` with `{"path":"ABSOLUTE_PATH_ON_OWNING_NODE"}`. The default audience is `lan`. Return the hub's ready URL: do not send localhost, raw IP, or filesystem paths as mobile links. The hub snapshots outputs and creates a mobile gallery; do not set up another file server or copy files manually. Only publish intended deliverables, never a whole repository, home folder, secrets, or unrelated inputs.

If the user needs access outside the network, call the same tool with `"audience":"external"`. Media Hub creates or updates Dropbox `/ai-workspace/<project>/<relativePath>` and returns a verified public share link plus `downloadUrl`. It infers the project and relative path from the configured projects root. For outputs elsewhere, pass `project` explicitly. Use `relativePath` to choose a stable destination inside the project, for example `{"path":"C:\\Users\\joeki\\projects\\rpg\\output\\dos2-lone-wolf-builds.html","audience":"external","project":"rpg","relativePath":"dos2-lone-wolf-builds.html"}`. Republish to the same destination to update the file and reuse its share link; do not add a UUID or timestamp unless a separate version is requested. Updates check the existing Dropbox revision; a concurrent change fails rather than silently replacing it. Folder uploads add/update included files and never delete omitted files. Existing UUID publications remain intact; they are not automatically migrated. Do not make internet copies by default. Only report success when `status` is `ready` and a URL is returned. On a failed or ambiguous upload, inspect the reported destination before retrying; do not invent a link or equate a local Dropbox copy with confirmed cloud sharing.

For a Dropbox direct-download share link, discover `media-hub.publish`, then use `call_tool` with the owning `nodeId`, `name: "media-hub.publish"`, and `input: { "path": "ABSOLUTE_FILE_PATH", "audience": "external", "project": "PROJECT_NAME" }`. This requires the user's request for internet sharing. Publish the individual file for an individual download; a folder publication returns a folder share link. The hub uploads through Dropbox's API and does not depend on desktop folder syncing. Require `status: "ready"`, then prefer the returned `downloadUrl`. For older results or existing share links, parse `url`, remove `raw`, set `dl=1`, and preserve `rlkey` and all other query parameters:

```js
const download = new URL(result.url);
download.searchParams.delete('raw');
download.searchParams.set('dl', '1');
const downloadUrl = download.href;
```

Return `[Download filename](downloadUrl)` using the actual URL. For an existing Dropbox share link, apply only the URL conversion; do not upload another copy. Never invent a share token or derive a public URL from a local path. `dl=1` requests downloading; `raw=1` requests browser rendering. Dropbox documents this at https://help.dropbox.com/share/force-download. If publication fails, follow the diagnostics and destination-inspection instructions below; changing URL parameters cannot fix a failed upload or missing sharing permission.

Run `media-hub.diagnostics` for setup or sharing failures; optionally pass the same `path`. Report which checks passed and any specific blocker. A check from the host does not prove phone DNS/firewall access. Dropbox read access does not prove upload or public-link permission; use `probeExternal:true` to test those with a temporary synthetic file and clean it up. Report cleanup failures. Never fall back to internet sharing without an external-sharing request.

Use `media-hub.transcript` for YouTube captions on either machine, then publish its returned text-file path if the user needs a mobile link. Poll image/voice job IDs and inspect results before reporting generation success. macOS exposes no model use. Credentials stay in native OS storage on the owning hub: never put them in chat, source, or `.env` files.

Claude may automatically generate voice when useful for the current task, without asking for separate voice-generation approval. Discover `voice` first, then prefer the dedicated MCP tools `voice_generate` with `nodeId` and `lines`, `voice_job` with `nodeId` and `id`, and `voice_download` with the same job ID. These call Media Hub's `voice.generate`, `voice.job`, and `voice.download`. Poll and inspect the completed job; do not blindly repeat an ambiguous submission. Use the Windows hub directly for voice, including from a Mac agent; the Mac hub remains files-only. External sharing still requires the user's request. Claude Code permissions are installed separately with `node scripts/install-voice-permissions.mjs` in the hub repository.

Claude may also automatically generate images when useful for the current task, without separate image-generation approval. Discover `media-hub.generate` and use the dedicated MCP tools: `image_configurations` with `nodeId`, `image_generate` with `nodeId` and `input` containing the discovered generation payload (including `prompt`), then `image_job` and `image_download` with `nodeId` and `id`. Use only enabled Windows models returned by discovery and the Media Hub catalog. The Windows catalog mirrors the original Image Studio models using isolated backend 8195. After an ambiguous submission, inspect `image_jobs` with `nodeId` before considering a retry. Inspect completed outputs before reporting success. Connect directly to Windows; the Mac hub remains files-only. Install Claude Code permissions with `node scripts/install-image-permissions.mjs` in the hub repository. This permission does not authorize new model installs or internet publication.

If MCP is unavailable, read the agent-tools repository's README and use its CLI (`node src/cli.mjs list`, then `node src/cli.mjs call NODE TOOL JSON`). A new agent session may be needed after MCP installation. Do not guess another service address.
